# 所有问题共用隔离讲解会话与单一时间轴契约

固定原型、人工编排讲解和后续生产运行时必须把每个问题作为独立讲解会话，并通过同一个讲解运行时模块协调旁白、字幕、动画、进度、片段切换、打断和恢复。预设、学科或关联主题不得在页面分支中自行创建、重置或跨接时间轴，也不得从 DOM 样式反推讲解业务状态。

这项决策把复杂时序和现场恢复收敛在一个小接口后，允许真实媒体、合成媒体和无媒体降级使用不同适配器；不锁定生产框架、媒体库、持久化技术或具体片段节奏。

## Contract

每个讲解会话至少声明：

- `runtime_contract_version`：运行时契约版本；
- `session_id` 与 `question_id`：问题级会话身份，任何命令和恢复现场都必须与二者匹配；
- `lesson_plan_version`：讲解计划及片段版本；
- `active_topic` 与 `active_segment`：当前主题和片段；
- `playback_state`：准备、播放、暂停、拖动、切换、完成、失败和降级状态；
- `timeline_position`：当前片段的权威时间位置；
- `scene_state`：已呈现内容、动画状态和必要的儿童操作结果；
- `interaction_state`：抽屉、录音、追问等与播放状态正交的交互状态；
- `capabilities`：当前问题和状态允许提交的命令集合；
- `snapshot_version`：可序列化讲解现场的版本。

调用方只通过 `dispatchLessonCommand(session, command)` 发送播放、暂停、拖动、切换、打断、恢复和交互提交命令，并消费运行时返回的新状态与事件。媒体、字幕、视觉场景和进度显示是该状态的适配器，不得各自成为权威时钟。

## Invariants

1. 每个问题拥有隔离的讲解会话。命令、媒体事件、延迟回调和恢复快照必须同时匹配当前 `session_id`、`question_id` 和计划版本；不匹配的事件必须被拒绝，不得改变其他问题、预设或主题。
2. 旁白、字幕、动画、进度和片段导航共用一个权威时间轴。允许不同媒体适配器提供时钟来源，但同一时刻只能有一个运行时状态决定所有输出。
3. 暂停必须冻结时间位置、已呈现内容和动画状态；恢复从同一讲解现场继续，不得重建、清空、从零计时或重复已经发生的揭示。拖动和片段切换必须根据目标语义位置确定性重建完整现场。
4. 真实音频不可用、自动播放受阻或媒体加载失败时，运行时可以切换到降级时钟，但不得启动第二条独立业务时间轴。降级必须继承当前状态、暂停位置和片段语义，并向界面返回可处理的显式状态。
5. 页面、主题、片段、播放、抽屉、录音和实验等状态必须独立建模并由运行时组合；DOM class、可见性、播放器标签或路由字符串不得作为业务状态的唯一来源。
6. 打断和返回使用带版本的语义快照，至少保存恢复所需的主题、片段、时间策略、已呈现内容及必要操作结果。具体是否恢复片段内时间由当前产品契约决定，但不得通过脆弱 DOM 快照或页面历史猜测恢复位置。
7. 所有用户命令必须先通过当前会话的 `capabilities` 校验。某入口需要可见但不可提交时，点击、键盘、长按、录音确认和延迟回调必须在同一命令接缝被一致阻断。
8. 片段准备时长、控件位置、C 端文案和特定问题的可用能力由 PRD 与交互规范决定，不属于运行时 ADR 的固定常量。

## Verification seam

原型和实际产品实现跨越同一个讲解运行时接口，并使用确定性时钟与合成媒体适配器验证状态转换。测试至少覆盖：正常连播、暂停与恢复、拖动前后重建、片段切换、主题打断与返回、真实媒体失败后降级、降级状态再次暂停、旧会话延迟事件、问题切换、受限命令及刷新后的兼容快照。

每次转换至少记录输入命令、前后会话身份、片段、时间位置、播放状态和拒绝原因；测试不得依赖真实等待时间或只通过截图判断时序正确。

## Consequences

- 新学科和新问题复用同一运行时模块，只提供讲解计划、场景和能力声明；
- 每个媒体、字幕、视觉和存储实现都是运行时接口的适配器，不能在页面分支中复制状态机；
- 契约、讲解计划或快照版本变化必须显式迁移或使不兼容现场失效；
- 精确片段节奏和问题特有交互继续由最新 PRD、原型及设计规范定义；
- 本 ADR 确认运行时接口与不变量，尚不证明生产媒体同步、现场恢复或跨设备持久化已经实现。
