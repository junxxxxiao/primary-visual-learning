# ChinaTextbook 数学与科学教材原子知识库成本评估

> 调研时间：2026-07-28
> 调研对象：[TapXWorld/ChinaTextbook](https://github.com/TapXWorld/ChinaTextbook/tree/5a80345f2043ba6f8db8d7be9cf3db82725ff1f7)
> 固定版本：`5a80345f2043ba6f8db8d7be9cf3db82725ff1f7`（仓库 `master`，2025-10-18）
> 结论性质：基于 GitHub 仓库完整文件树的可行性与量级评估，不证明教材版权可用、版本现行、内容完整或知识抽取准确。

## 1. 结论

把这些教材做成检索语料，算力和 token 成本不高；把它做成可用于儿童讲解、可追溯、可维护的“原子知识库”，成本主要在版权、图文公式抽取、跨版本去重和内容审核。

- 标准六三制核心范围约 `338` 本、`7.388 GiB`；如果把小学科学的 `58` 本学生活动手册也纳入，则为 `396` 本、`7.815 GiB`。
- 再纳入五四学制会增加 `60` 本、`0.733 GiB`，总量约 `398–456` 本、`8.12–8.55 GiB`（取决于是否纳入活动手册）。
- 规划阶段可按标准核心教材 `4.1–6.1 万页`、全量 `5.0–7.6 万页`估算。该页数是按每本教材页数区间外推，不是仓库实测页数；精确页数必须下载、合并分片后用 PDF 工具统计。
- 如果本地完成 PDF 文本抽取/OCR，只把规范化文本送去 embedding 和知识原子化，标准核心教材的一次性预算可先按 `0.8–2.5 亿 token`，全量按 `1.0–3.2 亿 token`。如果直接让多模态模型逐页读图并多轮校验，全量预算应按 `1.5–4.0 亿 token` 留量。
- 在线问答不应把全库塞进上下文。使用混合检索和重排后，每题通常只需约 `0.7–2.2 万 token`（问题与学习状态、检索证据、规划和讲解输出合计）。
- 最大阻断项是授权：GitHub API 返回 `license: null`，仓库根目录也没有 `LICENSE`。仓库公开和 README 的公益动机不等于获得教材内容的复制、改编、商用或模型处理授权。

因此，建议先做一个 `24` 本分层样本的 P0 技术切片，而不是立即全量录入。只有在版权路径和抽取质量门槛都通过后，才值得扩到全库。

## 2. 仓库实测范围

GitHub recursive tree API 在固定 commit 上返回 `truncated: false`，因此本次文件树统计是完整清单，而不是 GitHub 页面抽样。全仓库共有 `3,112` 个 tree entry、`2,375` 个 blob，blob 总大小约 `43.42 GiB`。本评估只纳入小学和初中的数学、科学及自然科学科目，不纳入练习题目录、高中和大学教材。

标准六三制口径为：

```text
小学/{数学,科学}
初中/{数学,物理,化学,生物学,科学}
```

其中 `.pdf.1`、`.pdf.2` 等分片，以及 `*.pdf_merge_folder/` 下的分片，按文件名归并为一本逻辑教材。小学科学的“学生活动手册”单列为可选教辅，不混入核心教材。

| 科目 | 版本目录数 | 逻辑教材数 | 仓库存储量 |
| --- | ---: | ---: | ---: |
| 小学数学 | 8 | 96 | 2.364 GiB |
| 小学科学（含活动手册） | 8 | 154 | 1.732 GiB |
| 其中：小学科学核心教材 | 8 | 96 | 约 1.305 GiB |
| 初中数学 | 10 | 60 | 1.464 GiB |
| 初中物理 | 7 | 22 | 0.854 GiB |
| 初中化学 | 6 | 12 | 0.316 GiB |
| 初中生物学 | 7 | 28 | 0.762 GiB |
| 初中科学 | 4 | 24 | 0.322 GiB |
| **标准制核心合计** | - | **338** | **7.388 GiB** |
| **标准制含活动手册** | - | **396** | **7.815 GiB** |

五四学制目录另有 `60` 本：小学数学 `10`、小学科学 `20`、初中数学 `16`、物理 `4`、化学 `4`、生物 `6`，合计约 `0.733 GiB`。五四学制没有发现独立的初中综合科学目录。

若把“科学相关”扩展到初中地理和地理图册，需作为第二个范围决策单独统计。地理包含大量地图、图表和空间关系，逐页视觉理解及事实版本核验的成本会显著高于纯文本 OCR，不建议默认混入第一阶段。

## 3. 文件格式与可抽取性

目标教材几乎都是 PDF blob，但不能把“文件扩展名是 PDF”视为已有可检索文本：

- [仓库 README](https://github.com/TapXWorld/ChinaTextbook/blob/5a80345f2043ba6f8db8d7be9cf3db82725ff1f7/README.md)说明，大于 `50 MB` 的 PDF 会拆成约 `35 MB` 的 `.pdf.N` 文件，使用前需要合并。
- 在本次标准制统计中，`19` 本只以分片存在，`9` 本同时存在完整 PDF 和分片，`368` 本只有完整 PDF。全量 ingest 前必须先合并并按内容 hash 去重，否则会漏书或重复索引。
- GitHub tree API 只提供路径、类型和字节数，不提供页数、字体、文本层或扫描质量。当前无法仅由远程文件树证明多少 PDF 可直接 `pdftotext`、多少必须 OCR。
- 数学和科学教材含公式、表格、坐标系、实验步骤图、标注图和跨栏排版。即使正文有文本层，公式与图中标签仍可能丢失或顺序错误；“能抽出字”不等于能生成可靠讲解。

全量前应对 `24` 本样本做分层抽检：小学/初中、数学/各科学科、低/中/高年级、至少六个出版社版本，并覆盖完整 PDF、仅分片 PDF 和“完整文件 + 分片”三类。至少记录：

1. 合并和渲染成功率、页数、文件 hash；
2. 有效文本层页占比、抽取字符数/页、乱码率和阅读顺序；
3. 正文 OCR 字符错误率、公式结构准确率、图中标签召回率；
4. 目录、页码、章/节/活动/例题结构恢复率；
5. 无法可靠抽取时的整页视觉解析比例和人工复核工时。

## 4. 页数和 token 估算

### 4.1 估算口径

文件树没有页数，以下仅用于容量规划：

- 核心教材按 `120–180` 页/本；
- 小学科学活动手册按 `60–100` 页/本；
- 五四学制新增教材按 `100–160` 页/本；
- 规范化后的正文、题目、公式线性表示和图注按 `300–600 token/页`；
- 逐页高细节视觉输入按 `1,000–3,000 token/页` 的模型无关规划区间；实际值必须按选定模型的图像计费规则复算。

| 范围 | 估算页数 | 规范化语料 token | 逐页视觉输入 token |
| --- | ---: | ---: | ---: |
| 标准制核心 338 本 | 4.1–6.1 万 | 1,200–3,600 万 | 4,100–18,300 万 |
| 标准制含活动手册 396 本 | 4.4–6.7 万 | 1,300–4,000 万 | 4,400–20,000 万 |
| 含五四学制全量 456 本 | 5.0–7.6 万 | 1,500–4,600 万 | 5,000–22,800 万 |

“语料 token”不是最终 ingest 账单。原子化还会产生结构化输出，并经历去重、校验和失败重试。建议预算：

| 环节 | 标准核心预算 | 全量预算 | 说明 |
| --- | ---: | ---: | --- |
| 本地 PDF/OCR | 0 API token | 0 API token | 有机器和工程成本；不代表免费或准确 |
| 清洗后 embedding | 1,200–3,600 万 | 1,500–4,600 万 | 通常只需一次，增量更新按变更重算 |
| LLM 原子化、关系抽取、去重与自动复核 | 6,000–18,000 万 | 7,500–22,000 万 | 输入、结构化输出和重试合计 |
| **建议一次性总预算** | **0.8–2.5 亿** | **1.0–3.2 亿** | 本地 OCR 路线，含约 20% 返工余量 |
| **全页多模态路线** | **1.2–3.2 亿** | **1.5–4.0 亿** | 只应用于需要看图/公式的页面可显著降低 |

比 token 总量更重要的是知识建模口径。直接按每个版本逐章切块会得到约数万条来源片段，但跨版本去重后，稳定的课程知识节点可能只有数千个。建议保留两层：

- `source_fragment`：精确到版本、册、章、页和内容 hash 的来源片段；
- `knowledge_atom`：规范化概念、前置知识、常见误解、可视化 affordance、适用年级和多来源引用。

不要把模型生成的知识原子反写成“教材事实”。原子必须保留来源页、抽取方法、审核状态、版本和可撤回关系。

### 4.2 在线问答 token

检索时只送入与问题相关的证据：

| 在线环节 | 单题规划值 |
| --- | ---: |
| 问题、OCR 输入摘要和学习状态 | 2,000–6,000 token |
| 混合检索后证据与邻接知识 | 4,000–12,000 token |
| 讲解计划、场景 Schema 和回答 | 1,000–4,000 token |
| **单题合计** | **7,000–22,000 token** |

这里不含图片输入、语音转写和多轮追问。缓存相同知识原子、把教材证据与用户会话分离、先检索再生成，可以避免语料规模线性推高每题成本。

## 5. 版权、版本与更新风险

### 版权

- [仓库 API 元数据](https://api.github.com/repos/TapXWorld/ChinaTextbook)返回 `license: null`；固定 commit 的根目录文件树中没有 `LICENSE`。
- [README](https://github.com/TapXWorld/ChinaTextbook/blob/5a80345f2043ba6f8db8d7be9cf3db82725ff1f7/README.md)只说明收集和开放资源的动机，没有教材权利人的授权范围、可商用条款、改编权、再分发权或模型训练/处理条款。
- 因此，该仓库最多能作为“教材清单和技术抽样入口”，不能直接成为生产知识库的合法内容源。上线前需要出版社/权利人授权或更换为明确可用的课程标准、官方开放资源和自研内容。

### 版本和完整性

- 固定版本最新提交 `5a80345` 只修改 README；部分教材目录最后更新停留在 2023–2024 年。
- 仓库只有一个 branch、没有 tag 或 release，教材文件名通常没有出版年份、印次、课程标准版本和 ISBN。
- README 没有覆盖率、缺册检查、勘误、现行性或内容审核保证。不同学制、出版社、旧版和新版可能并存，也可能缺册。
- 生产库需要独立的 `publisher / isbn / edition / curriculum_standard / publication_date / valid_from / valid_to / source_hash / rights_status / review_status` 元数据，不能从目录名猜测。

## 6. 推荐实施边界

第一阶段只做 `24` 本授权或可合法使用的样本，不承诺全学段覆盖。目标是验证一个可证伪问题：能否以可接受成本，将教材页稳定转换成带页级引用、结构正确、可检索且不会跨版本串台的知识原子。

通过门槛建议至少包括：

- `100%` 文件可合并、渲染并建立内容 hash；
- 正文 OCR 字符错误率 `<= 2%`，公式和图中关键标签另行人工评分；
- 章/节/页引用恢复率 `>= 99%`；
- 抽样知识原子的事实与来源页一致率 `>= 98%`，错误必须能定位到抽取步骤；
- 同一知识点跨版本合并时保留差异，不覆盖来源表述；
- 未授权、版本不明或质量未过门槛的内容不得进入在线检索。

若切片通过，再按“一个主要版本的数学 + 小学科学 + 初中物理/化学/生物/综合科学”逐批扩展。活动手册、五四学制、地理和其他出版社版本应分别立项，不要一次全收。

## 7. 已验证与未验证

已验证：

- 固定 commit、完整 recursive tree、文件路径、blob 数量和字节数；
- 目标科目和五四学制目录的逻辑书目数；
- PDF 分片、重复形态和 README 的合并规则；
- 仓库没有声明开源许可证。

仍未验证：

- 全量精确页数、PDF 文本层覆盖、扫描分辨率和 OCR/公式抽取准确率；
- 每本教材的 ISBN、版次、课程标准年份、现行性和缺册情况；
- 出版社或其他权利人是否授权该仓库传播，以及本项目的检索、改编和商业使用权；
- 真实 embedding/原子化 token、模型单价、端到端延迟和人工审核工时；
- 教材原子库是否实际提高答疑正确率、讲解质量或学习效果。
