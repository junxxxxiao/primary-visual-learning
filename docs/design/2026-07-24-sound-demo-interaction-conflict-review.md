## 1. 审查依据与判定方法

本审查读取了仓库根目录、`design/`、`design/high-fidelity/`、`docs/design/` 和 `prototype/` 的目录约束，以及：

- 当前高保真稿：`design/high-fidelity/sound-demo-screen-concepts.html`；
- 页面与状态矩阵：`docs/design/2026-07-23-sound-value-demo-page-state-matrix.md`；
- 已确认声音 Demo 规范：`docs/design/2026-07-22-sound-value-demo-spec.md`；

- 现有逻辑：`prototype/index.html`、`prototype/styles.css`、`prototype/app.js`、`prototype/config.js` 及固定音频资源说明。

判定使用四类冲突：

- **路由 / 状态**：页面是否能进入、返回、自动前进，或状态是否有对应逻辑；
- **操作语义**：按钮、Tab、输入、门禁、提交动作是否一致；
- **内容 / 数据边界**：是否泄露答案、暗示真实能力、扩大保存范围；
- **视觉状态覆盖**：静态稿只展示了某个已完成状态，无法代表实现所需的初始、加载、失败或恢复状态。

代码依据主要来自 `prototype/app.js`：公开入口和输入在 446–534 行，校准 / 预测 / 准备在 482–555 行，核心讲解和实验在 557–635 行，迁移 / 反馈 / 结果在 637–680 行，路由和返回在 768–822、970–1055 行，播放与追问恢复在 300–358、997–1044 行。高保真页面对应区段在 `sound-demo-screen-concepts.html` 862–1005 行。

## 3. 跨页面与数据边界结论

### 3.1 路由和返回

- 公开 Demo 的主链路 `publicEntry → ask → confirm → calibration → prediction → loading → explore → migration → feedback → complete` 在原型中存在；高保真以 S01–S15 表达同一链路。
- 原型 `explore` 顶部返回直接指向 `publicEntry`，符合 2026-07-23 补充“讲解页返回公开 Demo 入口”，但不符合高保真 S08 返回确认稿和 PRD 的“返回前保存 / 明确路径”。应补一个确认状态，而不是改回旧儿童首页。
- 原型仍保留 `home`、`history`、`parent*`、`failure` 等研究直达画板；公开模式默认隐藏研究导航，`?research=true` 才可见。这些页面不应被高保真实现或公开 CTA 引入。
- `popstate` 当前直接 `goTo('home')`，与公开 Demo 返回入口不一致；属于研究原型的旧路由残留，接入高保真时应明确是否纳入范围。

### 3.2 输入、校准与预测

- 当前原型的固定问题、来源匹配确认旁白、顺序校准、预测不揭示答案均是已验证逻辑；高保真主要需要收敛视觉，而不是删除这些状态。
- S02“可编辑输入”是最重要的边界风险：公开 Demo 规范与 PRD 的公开 Demo 条目都说固定、不提供任意问题。除非用户明确扩大范围，否则不应把静态 composer 做成可编辑或暗示真实 OCR / ASR。

### 3.3 讲解、实验与 Tab

- 原型把讲解、实验和关联主题复用为 `explore` 路由状态；高保真要求 S09 独立“实验”Tab。两者不是单纯 CSS 差异，接入时需决定 Tab 是否为真正的可操作导航，还是仅作为当前状态标签。
- 已确认顺序是：核心三段完成后开放迁移；实验、慢放和真空追问均不阻塞迁移。任何把“实验完成”设为迁移门禁的实现都应删除。
- 讲解期间不显示可拖动琴弦；只有 `lessonComplete` 后才出现实验区。高保真静态稿的“可拨动”画面必须标成 S09 状态，不能作为 S08 默认。

### 3.4 追问、手机小知与恢复

- 原型已有两条手机路径：轻点打开抽屉，以及长按约 280ms、松开自动提交；同时保留麦克风模拟录入后显式发送路径。高保真只画了录音中态，不能取代默认、取消、转写完成和发送后的状态。
- 真空主题不得继续追问：输入为空、麦克风和发送禁用；原型已实现。高保真中的“继续问这个问题”视觉应改为禁用或仅作非交互占位，否则会与数据边界冲突。
- 打断保存的是主题、子片段、力度、慢放和完成状态，不保存子片段内时间；儿童端不展示锚点和内部保存状态。高保真 S11 应表现自然连接语，不应新增“恢复到 01:23”之类文案。

### 3.5 结果和数据边界

- 结果页应只展示固定 Demo 的结构化证据：迁移结论、因果解释、实验 / 追问是否完成、完成方式和家庭协助未确认；不展示长期画像、排名、来源、真实模型能力或儿童个人信息。
- `config.js` 仅允许本地 `SURVEY_URL`；未配置时原型 Toast 提示，已配置时当前浏览器打开外部问卷。高保真应提供两种可审阅状态，但不能加入群二维码或联系方式。
- 原型中的 `records` 和 `parentRecordsData` 是旧研究画板固定夹具，不等于公开 Demo 保存真实历史。接入公开高保真时不要把历史、家长工作台或“重新从节点继续问”带入 S15。

## 4. 可直接实施的无争议项

1. 将高保真所有“默认已选正确答案”改成未选择初始态，并为已选 / 部分选 / 禁用提交另出状态稿。
2. 保留固定问题、无权限、无登录、无个人信息声明；S02 的 composer 明确为预置只读问题。
3. 在 S03 保留来源匹配旁白的自动播放能力，但不在 C 端展示旁白卡、播放按钮或实现说明；移除不必要的来源卡和重复学习目标信息。
4. 补齐 S04 初始、响度已听、两组已听三态；保留先响度后音调的门禁。
5. 补齐 S06 自动前进、S07 自动引入、S08 三段连播 / 1 秒预览 / 暂停 / 拖动 / 完成态的页面状态；不增加失败入口。
6. 实验保留先轻后重、连续两次无效操作后保底按钮、慢放可选、迁移不依赖实验完成的逻辑。
7. 补齐 S10 手机挂件轻点抽屉、按住快捷发送、模拟录入中、转写完成、取消、发送后收起；真空主题输入禁用。
8. 补齐 S11 三段真空、连接语、控制禁用、自动回 S08 子片段开头，以及手机浮层不压缩原画布的状态。
9. 补齐 S12–S15 的初始 / 部分 / 失败 / 通过 / 未配置问卷状态，并让反馈补充原因要么可保存、要么不显示。
10. 保持公开路由返回 `publicEntry`，不把旧 `home`、历史和家长画板接入公开 CTA。

## 5. 已确认的产品取舍（无需再次决策）

1. **S02**：默认问题预填，但输入框允许真实打字编辑；语音 / 拍照仍使用固定模拟输入，不扩展任意问题能力。
2. **S07**：不保留开始按钮，也不保留重听按钮；进入后自动播放并继续到 S08。
3. **S09**：采用高保真“实验”Tab 语义，但实验完成不作为迁移门禁；保留先轻后重与无效操作保底。
4. **S10**：录音完成后对勾直接提交；叉号取消本次录入并留在抽屉默认态。
5. **S14**：补充原因支持多选并保存为结构化反馈。
6. **S06**：准备等待固定约 3.2 秒；不在 C 端展示具体秒数。

## 6. 建议的交互实施顺序

1. **先锁边界和默认态**：S01–S05；固定只读问题、来源旁白、校准门禁、预测未选择态。
2. **再接入自动时序**：S06–S08；统一准备自动前进、S07 引入策略、三段播放、1 秒预览、暂停 / 拖动和 S08 返回确认。
3. **再接入实验状态**：S09；先轻后重、拖动失败、保底按钮、慢放、实验 Tab 与迁移非门禁。
4. **再接入追问和恢复**：S10–S11；先实现平板常驻对话，再实现手机抽屉、长按、录音状态、显式发送、连接语和自动恢复。
5. **最后接入收口证据**：S12–S15；迁移两维判定、木琴提示、反馈记录、三类结果、问卷两态和重新体验。
6. **完成四个视口验收**：`360×800`、`390×844`、`1180×820`、`1366×768`，并逐一复核键盘焦点、减少动态效果、控制台错误、无滚动 / 遮挡和返回状态。

## 7. 明确未验证内容

- 本次是静态设计与现有代码的文档审查，没有修改或运行浏览器交互，不代表高保真接入后已通过验收。
- 未验证真实儿童能否理解 S02 单 composer、S03 旁白、S09 实验 Tab 或 S10 长按 / 抽屉手势。
- 未验证实体触摸设备上的拖动琴弦、长按防系统菜单、播放自动续播和旋转恢复。
- 未验证浏览器自动播放策略、真实音频时长、音画同步、减少动态效果下的信息等价性或四个基准视口无溢出；这些仍应按声音 Demo 规范重新验收。
- 未验证外部问卷提交、`SURVEY_URL` 配置后的跳转和问卷完成后的入群承接。
- 固定夹具和当前原型不证明真实 OCR、ASR、任意问题、动态生成、知识正确率、儿童学习效果、生产稳定性或付费价值。

## 8. 总结

最需要先处理的不是颜色或组件，而是三个会改变证据含义的交互冲突：S02 是否仍为固定只读问题、S05/S12/S13 默认态不能泄露答案、S10 的录入完成是否需要显式发送。其次是 S07 的自动前进、S08 返回确认和 S09 实验 Tab；这些决定高保真能否真实表达已有的播放、实验和现场恢复逻辑。
