# 小学互动视觉家教技术可行性验证与切片准备

> **文档状态：已被 [技术验证 v2](2026-07-22-primary-visual-tutor-technical-validation-v2.md) 替代，仅保留为历史记录。**

> 版本：v1.0  
> 日期：2026-07-17  
> 对应 PRD：[小学互动视觉家教 PRD](../product/2026-07-17-primary-visual-tutor-prd.md)  
> 文档目的：明确当前必须验证的技术实现点，并为后续编写可独立运行的技术切片脚本提供输入、夹具、指标和通过标准

## 0. 文档边界

本文不是生产架构设计，也不是开发排期。它回答四个问题：

1. 哪些原型能力存在真实技术不确定性？
2. 每个不确定性最小应验证到什么程度？
3. 用什么固定夹具、数据和指标判断可行或不可行？
4. 切片之间如何排序，哪些结果会改变 PRD 或高保真设计？

原则：

- 一个切片只回答一个主要可行性问题；
- 优先验证会推翻产品核心闭环的风险；
- 所有模型输出使用结构化契约和可审计版本；
- 固定夹具、真实样本和人工评分分开记录；
- 不用“演示跑通一次”替代稳定性测量；
- 不以平均值掩盖 P95、失败率和严重错误；
- 切片可以使用临时代码，但输出契约、指标和失败样例必须可复用。

## 1. 当前技术可行性总判断

### 1.1 普通工程实现，不是核心技术风险

以下内容仍需开发和测试，但原则上不需要先做独立技术切片：

- 首页、问题确认、预测、反馈和完成页的常规 UI；
- 桌面 / 平板双栏与手机纵向响应式布局；
- 手机卡通挂件和底部对话抽屉；
- 家长记录分类、原位展开和锚点滚动；
- 普通表单、筛选、PIN 原型交互和删除确认弹窗；
- 设计 Token、组件库和高保真视觉实现。

这些功能可以在真实技术能力边界确定后正常开发。

### 1.2 会决定产品是否成立的技术风险

P0 可行性问题：

1. 微信环境下儿童语音、拍照、音频播放和互动渲染是否能稳定共存；
2. 系统能否把问题、知识、误解假设和教学目标转换为受控结构，而不是自由文本；
3. 模型能否可靠选择、参数化和修改受控视觉组件；
4. 追问时能否立即保存现场，并在分支结束后无损恢复；
5. 首个有效讲解能否渐进生成，并在失败时可靠降级；
6. 语音、文案、视觉状态和当前子片段进度能否共用一个同步时间轴；
7. 探索记录能否通过事件流重建、回放和分支，而不是保存视频。

P1 生产化问题：

1. 拍照 OCR、框选、教材映射和隐私遮挡；
2. 儿童内容安全、事实依据、审核与版本修订；
3. 儿童数据授权、期限、级联删除和成人验证；
4. 迁移结果、主观反馈和家长记录分类；
5. 真实设备性能、成本、日志和故障定位；
6. 近期学习画像的证据门槛与重算。

## 2. 建议的技术架构假设

本阶段建议验证以下解耦结构，而不是直接建设完整系统：

```text
拍照 / 语音 / 文字
        ↓
问题理解与隐私处理
        ↓
知识节点检索 + 误解候选 + 置信度
        ↓
受控讲解规划（主题 / 子片段 / 教学策略）
        ↓
视觉组件选择 + 参数 / 命令生成
        ↓
场景运行时 + 统一播放时钟
        ↓
追问控制器 ── 修改原场景 / 创建主题 / 降级
        ↓
事件流、快照、学习证据和内容版本
        ↓
儿童回放 / 家长记录 / 近期归纳
```

必须保持的边界：

- 模型不直接生成并执行任意前端代码；
- 知识事实与场景表现分离；
- 场景命令必须经过 Schema 校验和运行时白名单；
- 讲解内容、场景、语音和审核版本必须可追踪；
- 回放只消费已保存事件，不重新调用模型；
- 事实修订不会静默篡改历史。

## 4. 公共验证夹具

### 4.1 黄金声音夹具

- 问题：用力拨琴弦，声音会更高吗？
- 条件：同一根弦，弦长、松紧和粗细不变；
- 误解候选：力度越大，音调越高；
- 原场景命令：轻拨、用力拨、慢放、恢复速度；
- 关联追问：如果没有空气呢？
- 主题：琴弦振动 → 真空中的声音；
- 迁移：同一音叉被更用力敲击，音调是否改变。

### 4.2 黄金分数夹具

- 问题：为什么四分之一比三分之一小？
- 误解候选：分母数字越大，分数越大；
- 场景：同样大的整体分别平均分成 3 份和 4 份；
- 操作：切换整体形状、份数和高亮份；
- 迁移：更换整体形状后比较两个单位分数。

### 4.3 负向夹具

至少包含：

- 模糊照片、倾斜课本、含姓名 / 学校的页面；
- 儿童口音、重复、停顿、背景噪声和半句追问；
- 无关追问、危险实验、成人内容和隐私索取；
- 知识库未覆盖的问题；
- 模型输出非法组件、非法参数和自相矛盾事实；
- 网络中断、模型超时、TTS 失败、场景渲染失败；
- 删除存在后代分支的探索；
- 回放旧版本内容并继续使用新版本知识。

### 4.4 样本分层

每个切片至少区分：

1. 合成固定夹具：用于重复回归；
2. 成人模拟儿童输入：用于早期调试；
3. 经授权的真实儿童样本：用于真实准确率与延迟测量；
4. 对抗 / 边界样本：用于安全和降级；
5. 教师审核集：用于知识和教学适切性评分。

真实儿童样本必须取得监护人明确授权，且原始语音 / 照片按切片说明限时保存和删除。

## 6. 技术切片定义

## TS-00 微信 / H5 运行时能力

### 验证假设

目标微信小程序或 H5 容器能够在同一页面稳定完成录音、TTS 播放、动画 / Canvas 渲染、触摸交互、暂停恢复和本地临时状态保存。

### 最小切片

- 一个微信小程序壳和一个 H5 壳；
- 录音开始 / 结束；
- 播放一段 20 秒 TTS；
- 同时运行琴弦互动场景；
- 切后台 5 秒后返回；
- 手机抽屉展开、关闭；
- 记录帧率、内存、音频中断和权限行为。

### 设备矩阵

- iOS 微信主流版本；
- 安卓微信主流版本；
- iPad Safari / 微信；
- 中端安卓平板；
- 至少一台较低性能安卓设备。

### 通过标准

- 录音和播放状态可预测，权限拒绝有明确回退；
- 音频暂停后位置误差不超过 250 ms；
- 目标场景连续运行无崩溃、无明显内存增长；
- 交互期间帧率满足可理解操作，建议 P95 不低于 30 FPS；
- 前后台切换后能够恢复或明确重新开始；
- 小程序包体、分包和资源加载方案可接受。

### 失败后决策

- 小程序限制不可接受：先用 H5 / 原生壳验证；
- 低端性能不足：减少动画复杂度，使用 DOM / Canvas 2D 而非更重方案；
- 音频限制严重：调整为点击录音和显式播放，不承诺无缝全双工。

## TS-01 输入、OCR、儿童语音与隐私预处理

### 验证假设

在首批概念范围内，系统能将拍照、儿童语音和文字统一成可确认的问题文本，并识别敏感信息和低置信度状态。

### 最小切片

- 拍照裁剪、旋转校正、OCR；
- 姓名、学校、人脸等隐私检测；
- 儿童普通话语音转写；
- 支持短追问和课堂背景噪声；
- 输出 QuestionEnvelope；
- 置信度低时生成最多 3 个候选或要求重试。

### 关键指标

- OCR 字符 / 词错误率；
- 题干和框选区域提取正确率；
- 儿童语音词错误率、关键概念召回率；
- 从停止说话到确认文字出现的 P50 / P95；
- 隐私检测召回率和误遮挡率；
- 低置信度校准：错误样本是否真的获得更低置信度。

### 候选通过标准

- 黄金概念关键实体和问题意图召回率 ≥ 90%；
- 错误识别不自动进入讲解，能够通过确认页纠正；
- 高风险隐私漏检为 0（在限定测试集内）；
- 语音 / OCR 失败均能退回文字输入。

## TS-02 可信知识检索、问题理解与误解候选

### 验证假设

受控知识库加结构化模型输出能够稳定识别知识节点、学习目标、适用边界和误解候选，并在置信度不足时主动澄清。

### 最小切片

- 仅覆盖声音和分数两个知识簇；
- 每个簇准备审核知识原子、来源、常见误解和诊断问题；
- 输入 100–200 条变体问题；
- 输出 DiagnosisEnvelope；
- 教师对知识节点、学习目标、误解候选和边界进行盲评。

### 关键指标

- 知识节点 Top-1 / Top-3 正确率；
- 学习目标准确率；
- 误解候选准确率与置信度校准；
- 应澄清时的澄清召回率；
- 严重事实错误数；
- 输出 Schema 合法率。

### 候选通过标准

- 知识节点和学习目标正确率 ≥ 90%；
- 严重知识错误为 0；
- Schema 合法率 ≥ 99%；
- 低置信度样本不会被伪装成确定诊断；
- 每个结论可追踪到审核来源和内容版本。

## TS-03 受控讲解规划

### 验证假设

系统能把诊断结果转换为 2–4 个短子片段，并为每个子片段生成适龄文案、视觉目标、允许控制和降级方式。

### 最小切片

- 输入 DiagnosisEnvelope；
- 输出 LessonPlan；
- 固定三种策略：控制变量、并排比较、反事实；
- 对同一输入重复生成 30 次；
- 由小学教师和产品人员评分。

### 检查项

- 是否一次一个重点；
- 是否符合三 / 四年级语言；
- 文案与视觉目标是否一致；
- 是否引入未审核事实；
- 互动控制是否服务教学目标；
- 是否总有非互动降级；
- 重复生成是否保持结构稳定。

### 候选通过标准

- LessonPlan Schema 合法率 ≥ 99%；
- 关键教学顺序人工通过率 ≥ 90%；
- 文案与视觉目标矛盾率 < 2%；
- 任何片段均有可执行场景或明确降级；
- 未审核事实进入计划为 0。

## TS-04 视觉场景 DSL、组件映射与安全运行时

### 验证假设

通过参数化组件库和受限 SceneCommand，可以覆盖黄金问题的原场景变化和关联主题，不需要模型生成任意前端代码。

### 最小切片

实现两个组件：

1. StringVibrationScene：力度、速度、振幅标注、空气 / 真空；
2. FractionPartitionScene：整体形状、份数、高亮份、并排比较。

实现：

- JSON Schema 校验；
- 参数范围、枚举和状态迁移白名单；
- 非法命令拒绝；
- 场景状态序列化 / 反序列化；
- 同一命令重复执行的幂等性；
- 静态图解降级。

### 关键指标

- 合法命令执行成功率；
- 非法命令拦截率；
- 场景状态 round-trip 一致性；
- 命令到可见变化的延迟；
- 组件覆盖黄金路径的比例；
- 不同设备的渲染性能。

### 候选通过标准

- 黄金路径 100% 可通过受控命令完成；
- 非法组件 / 参数执行为 0；
- 序列化再恢复后的状态深度一致；
- 场景命令 P95 可见响应 < 300 ms（不含模型推理）；
- 每个互动状态均有静态图解降级。

## TS-05 追问、快照、原场景修改与主题恢复

### 验证假设

追问发生时可立即保存当前现场；控制器能区分“修改原场景”和“创建关联主题”；返回原主题时恢复完全一致。

### 最小切片

在声音夹具中实现：

1. 子片段 2 播放到 8.2 秒；
2. 用力拨、0.4× 慢放；
3. 发起“可以慢一点吗？”并修改原场景；
4. 发起“如果没有空气呢？”并创建新主题；
5. 在两个主题间切换；
6. 返回琴弦主题并恢复 8.2 秒、用力拨和 0.4×；
7. 重复 100 次并注入网络延迟 / 重复事件。

### 关键指标

- 追问意图路由正确率；
- 快照保存延迟；
- 恢复后主题、子片段、时间和参数一致率；
- 重复事件和乱序事件下的稳定性；
- 分支返回成功率；
- 用户看到“已暂停”的时间。

### 候选通过标准

- 本地暂停反馈 < 150 ms；
- 快照写入不阻塞 UI；
- 黄金路径恢复一致率 100%；
- 重复 / 重试不产生重复主题或重复事件；
- 路由不确定时先澄清，不错误修改场景。

## TS-06 渐进生成、延迟预算与降级

### 验证假设

诊断预测期间并行准备开头讲解，可以在完整互动内容未准备好时先开始有效解释；任何关键失败都有确定降级路径。

### 最小切片

记录以下阶段时间：

- 输入完成；
- 问题确认；
- 知识检索完成；
- 开头文案完成；
- TTS 首字节；
- 首个图解可见；
- 互动组件可用；
- 完整计划完成。

注入：模型 3 / 8 / 15 秒延迟、TTS 失败、组件失败、网络中断。

### 关键指标

- Time to First Meaningful Explanation；
- Time to First Visual；
- Time to Interactive；
- P50 / P80 / P95；
- 自动降级成功率；
- 降级后事实和教学目标保持率；
- 重试是否重复扣费或重复写入。

### 候选通过标准

- 候选服务目标：80% 在 8 秒内出现可理解的首个讲解；
- 15 秒内开始或明确失败 / 降级；
- 追问 3 秒内先有确认反馈，8 秒内可见变化或降级；
- 关键组件失败时仍能用审核图解完成教学目标；
- 技术错误不直接暴露给儿童。

若达不到，应先调整 PRD 的等待、开头内容和支持范围，不应仅增加加载动画。

## TS-07 统一播放与同步引擎

### 验证假设

语音、逐步文案、视觉关键帧和当前子片段进度可以由同一时间轴驱动，并支持暂停、继续、切换和恢复。

### 最小切片

- 20 秒 TTS；
- 4 个文字 cue；
- 5 个视觉 cue；
- 播放、暂停、继续；
- 跳转到 5 / 10 / 15 秒；
- 切换子片段再返回；
- 前后台切换；
- 减少动态效果模式。

### 关键指标

- 语音与文字 cue 偏差；
- 语音与视觉 cue 偏差；
- 暂停 / 恢复位置误差；
- 多次跳转后的累计漂移；
- TTS 时长变化时 cue 重映射稳定性。

### 候选通过标准

- 正常播放 cue P95 偏差 < 250 ms；
- 暂停恢复误差 < 250 ms；
- 10 次切换后无明显累计漂移；
- 进度条始终表示当前子片段，不与主题总进度混淆；
- 减少动态效果时保留等价信息。

## TS-08 事件流、回放、分支与内容版本

### 验证假设

探索可以作为追加事件流保存；回放可确定性重建；从历史节点继续会创建新分支，不改写原历史。

### 最小切片

- 定义事件类型和 Schema；
- 保存完整声音黄金路径；
- 从空状态重放；
- 在任意节点创建分支；
- 重试、离线缓存、重复提交和乱序处理；
- 内容版本从 v1 修订到 v2；
- 删除原探索和单独删除分支。

### 关键指标

- 回放最终状态与原始状态哈希一致；
- 事件写入幂等率；
- 离线恢复成功率；
- 分支是否保持父事件不可变；
- 旧内容是否显示修订标识；
- 级联删除覆盖率。

### 候选通过标准

- 黄金路径回放状态一致率 100%；
- 重复事件不会重复应用；
- 分支不会修改父事件；
- 继续互动使用最新审核知识，但历史保留原版本；
- 删除后所有应删除数据不可再通过产品 API 读取。

## TS-09 儿童安全、事实审核和输出约束

### 验证假设

内容检索、模型规划和场景命令三层约束能够阻止危险、不适龄、隐私索取、无来源事实和误导性动画进入儿童体验。

### 最小切片

- 200 条安全 / 边界提示集；
- 50 条事实冲突或知识库未覆盖问题；
- 50 条诱导生成非法场景命令的输入；
- 输出分类、拒绝、澄清、受控回答和人工升级；
- 教师 / 安全审核双人评分。

### 候选通过标准

- 严重不适龄或危险输出为 0；
- 事实不确定时不生成确定性视觉结论；
- 未审核事实不能进入“可信知识”状态；
- 场景运行时始终拒绝非法命令；
- 每个回答可追踪来源、策略和内容版本。

## TS-10 隐私生命周期、权限与删除

### 验证假设

系统可以将原始媒体和结构化学习记录分开管理，落实授权期限、最小保存和级联删除。

### 最小切片

- 原始照片 / 语音临时存储；
- 转写完成后的自动删除；
- 30 / 90 天保存期限模拟；
- 关闭历史保存；
- 删除单次探索、删除分支、清空全部历史；
- 删除审计日志；
- 家长 / 儿童模式权限隔离。

### 候选通过标准

- 原始媒体超过规定临时期限仍存在为 0；
- 未授权数据不进入长期存储；
- 删除可级联至快照、事件、对话和派生画像；
- 删除操作可审计但审计日志不保留被删儿童内容；
- 四位 PIN 不作为生产级身份安全的唯一措施。

## TS-11 迁移判定、家长分类与近期归纳

### 验证假设

结构化学习证据足以稳定形成“已理解 / 部分理解 / 建议陪一陪”，并能解释分类依据。

### 最小切片

- 输入预测、提示次数、迁移答案、是否独立和主观反馈；
- 明确的规则基线；
- 模型辅助解释与规则结果对照；
- 处理主观 / 客观矛盾；
- 删除记录后重新分类和重算近期画像；
- 少于 5 次探索时显示证据不足。

### 候选通过标准

- 同一事件输入产生确定性分类；
- 分类可解释到具体证据；
- 主观和客观矛盾不被覆盖；
- 家长可从指标定位到对应记录；
- 近期画像不使用固定人格标签；
- 删除后不再引用已删证据。

## TS-12 可观测性、成本、负载与故障恢复

### 验证假设

全链路能够在不记录多余儿童敏感内容的前提下定位延迟、失败、事实版本和成本问题。

### 最小切片

每次请求记录：

- trace_id、exploration_id、阶段耗时；
- 模型 / ASR / TTS / 渲染供应方和版本；
- 输入输出 Token 或等价计费量；
- 缓存命中、重试、降级和错误码；
- 内容版本、场景 Schema 版本；
- 不包含原始儿童媒体的脱敏诊断摘要。

进行 1、10、50 并发测试和供应方超时注入。

### 候选通过标准

- 能从单次失败追踪到具体阶段；
- 能计算每次完整探索和每次追问成本；
- 重试和降级不会重复写入事件；
- 日志不包含未授权原始媒体和直接身份信息；
- 可按内容版本和设备类型分析失败率。

## 7. 技术切片脚本规范

后续每个切片建议使用统一目录：

```text
spikes/
  ts-04-scene-runtime/
    README.md
    fixtures/
    schemas/
    src/
    scripts/
    results/
    decisions.md
```

每个 `README.md` 必须包含：

1. 唯一验证问题；
2. 不验证什么；
3. 输入和输出 Schema；
4. 依赖和运行环境；
5. 固定夹具与真实样本说明；
6. 一条命令运行方式；
7. 指标定义；
8. 通过 / 失败门槛；
9. 数据与隐私处理；
10. 已知限制。

每次运行至少输出：

```json
{
  "slice_id": "TS-04",
  "run_id": "2026-07-17T120000Z",
  "environment": {},
  "fixture_version": "1.0",
  "metrics": {},
  "failures": [],
  "cost": {},
  "artifacts": [],
  "decision": "pass|conditional|fail"
}
```

禁止只输出“成功 / 失败”或截图。所有失败样本必须保留去标识化输入、预期、实际、错误类型和是否可重现。

## 8. 推荐执行顺序

### 阶段 A：载体与核心场景（先做）

1. TS-00 微信 / H5 运行时；
2. TS-03 受控讲解规划；
3. TS-04 场景 DSL 与运行时；
4. TS-05 追问与现场恢复。

阶段 A 的 Go 条件：

- 微信或备选载体可支持核心媒体与渲染；
- 模型输出能稳定映射到受控组件；
- 原场景修改和分支恢复确定性通过。

未通过时，应先缩小支持范围或调整产品载体，不进入完整高保真动效生产。

### 阶段 B：真实输入与体验性能

5. TS-01 输入管线；
6. TS-02 知识与诊断；
7. TS-06 渐进生成与降级；
8. TS-07 同步播放。

阶段 B 的 Go 条件：

- 真实儿童输入能经确认纠错后进入正确知识节点；
- 首个有效讲解和追问响应达到可接受水平；
- 失败有确定保底；
- 播放、暂停、切换和恢复不明显错位。

### 阶段 C：记录、生产安全与家长价值

10. TS-09 内容安全；
11. TS-10 隐私删除；

13. TS-12 可观测性和成本。

## 9. 会影响高保真设计的技术结论

高保真设计前至少需要拿到以下初步结论：

1. 语音录制是按住说话还是点击开始 / 结束；
2. ASR 是否支持流式文字，以及首字 / 最终文字的时间；
3. 主题和子片段是否可渐进到达，是否需要“内容尚未准备好”状态；
4. 当前子片段进度是否允许拖动；
5. 场景运行时支持哪些互动控制和组合；
6. 原场景修改的典型响应时间；
7. 追问确认、生成和降级有哪些中间状态；
8. 手机抽屉展开时是否需要暂停讲解；
9. 微信权限拒绝、后台恢复和音频打断的真实表现；
10. 保存成功、离线未保存和恢复失败的状态；
11. 哪些内容可以显示为“已审核”，如何呈现修订标识；
12. 家长身份验证和删除流程的真实安全要求。

这些结论决定按钮状态、加载状态、错误反馈、动效、权限弹窗和进度交互。未验证前，高保真稿应把它们标为“技术待定状态”，不能只画理想成功路径。
