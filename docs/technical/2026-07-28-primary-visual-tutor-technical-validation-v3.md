## 0. 变更摘要

v3.2 保留原 TS 编号和双学段验证边界，并增加真实生成视觉体验与统一计时门槛：

- 长期定位扩展为小学至初中数学与科学，但不把两个固定夹具外推为全年级覆盖；
- 公共契约显式携带学段、年级、教材版本和前置知识；
- TS-02、TS-03、TS-04B、TS-04C 使用小学科学与初中数学双夹具；
- TS-03 增加同一核心概念的受控双学段计划，隔离学段变量；
- TS-04B 先用确定性正负夹具证明教学与布局门禁有效；TS-04C 再消费 TS-03 的完整讲解计划，用冻结真实模型验证实际生成效果、一次修复、人工评审、耗时和成本；
- TS-07 移入 P0 并置于 TS-04C 与 TS-05 之间，先建立真实语音、字幕、动画和进度的统一时间轴，再验证拖动、追问与现场恢复；
- 所有切片使用 `StageTiming` v1.0 记录同一 trace 下的里程碑、局部 span、重试、缓存、Token 和成本；用户思考与确认时间不计入系统生成延迟；
- 学段和教材上下文允许缺失；缺失时不得自行猜测，记录为 `unknown` 并正常讲解；明确超前内容记录为 `advanced`，不作为阻断条件；
- 无知识原子且无可靠来源时进入带 C 端提示的 `unverified_generated` 路径，不得伪装为已核验内容或形成正式学习结果。

v2 已确认并由 v3 继续沿用的关键假设：

- 首个动态载体从“小程序或 H5 待定”改为“H5 核心体验 + 微信入口”；
- TS-04 从纯受控组件扩展为生成视觉代码、隔离沙箱和教学正确性契约；
- 教材 PDF、多阶段 AI 核验和临时知识包进入知识验证；
- 统一时间预算为 8 秒首个讲解、30 秒全新场景目标、约 45 秒硬降级；
- 增加固定安全响应、内容修订、熔断、30/90 天数据生命周期；
- 区分学习结果、完成方式、家庭协助和探索性证据。

本文件不是生产架构或开发排期。每个切片只回答一个可证伪问题，并记录适用范围、失败样例和对 PRD、设计、架构、数据及隐私的影响。

## 1. 公共夹具

### 1.1 小学科学：声音

- 主问题：更用力拨同一根弦，音调会更高吗？
- 词义校准：音调与响度；
- 双视图：琴弦慢放与振动记录图；
- 原场景追问：可以慢一点看吗？
- 关联追问：如果没有空气呢？
- 首次迁移：同一音叉；
- 提示后迁移：同一木琴音条。

### 1.2 初中数学：完全平方公式

- 固定题图中的完全平方配方、两道代数最值题和一道靠墙围花圃题；
- 迁移任务使用 120 米围栏，分别验证尺寸、最大面积和配方原因；
- 同题提示后答对只记录完成本题，不作为有效提示后迁移。

### 1.3 受控双学段配对夹具

使用“同一根弦在其他条件不变时，更用力主要改变振幅而不直接改变频率”这一核心关系，分别声明小学与初中学习者画像。核心事实保持一致，只改变允许使用的前置知识、术语、公式密度、视觉信息量和迁移难度，用于隔离学段变量。小学版本不得依赖尚未声明的代数或波动公式；初中版本不得仅复制小学文案并替换年级标签。

### 1.4 负向夹具

- 无可靠来源的问题；
- 未填写年级和教材的问题；
- 明确声明的超前学习路径；
- 来源冲突；
- 危险实验、医疗、隐私、不适龄和紧急安全问题；
- 诱导访问网络、存储、主 DOM、相机或麦克风的生成代码；
- 视觉表达与文字结论相反；
- 超时、崩溃、重复事件和乱序事件。

## 2. 公共契约

沿用 v1 的 QuestionEnvelope、DiagnosisEnvelope、LessonPlan、Snapshot 和 Event，并增加可选 `StageProfile` 与必填 `StageFit`。`QuestionEnvelope`、`KnowledgeAtom`、`LessonPlan`、`VisualArtifact` 和 `LearningResult` 必须保留已知的学段上下文；未知时显式记录，不保存不必要的儿童身份信息。

### 2.1 StageProfile

```json
{
  "context_status": "provided|partial|unknown",
  "school_stage": "primary|middle|null",
  "grade": "1-9|null",
  "curriculum": "国家课程标准版本|null",
  "textbook_edition": "教材版本|null",
  "prerequisite_refs": ["science.sound.vibration.basic"],
  "profile_version": "1.1"
}
```

首次设置中的年级和教材均可跳过。缺少学段、年级或教材上下文时不得从题目难度、用词或孩子身份推断，系统继续讲解并记录 `context_status=unknown|partial`。

### 2.2 StageFit

```json
{
  "status": "within_stage|advanced|ambiguous|unknown",
  "basis": "curriculum_source|textbook_source|learner_confirmation|none",
  "source_refs": [],
  "missing_prerequisite_refs": [],
  "fit_version": "1.0"
}
```

`advanced` 和 `unknown` 都允许正常讲解，C 端不显示超纲提示。意外串用其他学段来源仍失败；只有显式声明来源学段、前置知识和 `StageFit` 的超前路径才可通过。

### 2.5 ContentPackage 与 LearningResult

内容包增加 `verification_status=verified_atom|temporary_verified|unverified_generated|blocked`、`stage_fit` 和 `user_notice`。`unverified_generated` 必须显示一次固定提示，并禁止写入正式 `outcome`。

学习结果分别保存 `stage_profile_ref`（可空）、`stage_fit`、`outcome`、`completion_method`、`system_assistance`、`family_assistance`、`evidence_status` 和具体迁移维度。家庭协助缺失为 `unknown`，不得推断。未核验生成只保存探索记录和反馈，不生成“自己弄懂了”等结果。

### 2.6 StageTiming 与统一统计口径

所有切片使用 `spikes/shared/schemas/stage-timing.schema.json` 的 `StageTiming` v1.0。里程碑只标记事件发生时间，span 才表示一段耗时。`question_confirmed` 是孩子点击确认后的用户感知等待零时刻，不是一段系统耗时；`input_result_visible → question_confirmed` 的阅读、修改和决定时间标记为 `user_action_excluded`，不得进入生成性能分母。

公共里程碑名称为：

```text
input_result_visible
question_confirmed
first_meaningful_content
lesson_plan_completed
visual_generation_completed
sandbox_check_completed
visual_validation_completed
interactive_ready
fallback_ready
```

切片按职责记录 `input.asr|input.ocr`、`knowledge.local_gate|knowledge.model_audit`、`lesson.plan|lesson.transfer`、`visual.generate|visual.repair`、`sandbox.create|sandbox.worker_boot|sandbox.execute|sandbox.terminate|sandbox.destroy`、`visual.validate|cache.read|cache.invalidate`、`timeline.prepare|timeline.seek|timeline.resume`、`snapshot.save|snapshot.restore` 等 span。字段至少包含单调时钟起止、`duration_ms`、结果、重试序号、缓存状态、供应方/模型、计费量、费用和机器可读错误码。

统计必须：

- 按成功、失败、超时和降级分别报告样本数、P50/P80/P95、最大值和失败率；平均值只作补充，不能单独作为门槛；
- 冷启动、热启动、缓存命中/未命中、首次生成/修复、手机/平板、小学/初中分别报告，不得混合后用总体平均掩盖长尾；
- 所有并行 span 使用同一单调时钟，端到端耗时直接由公共里程碑相减，不能把并行局部耗时简单相加；
- 后台预生成标记为 `background_speculative`，同时记录孩子确认后的实际等待与取消/修改造成的浪费成本；
- `question_confirmed → first_meaningful_content`、`question_confirmed → interactive_ready` 和 `question_confirmed → fallback_ready` 只由 TS-06 做最终端到端判定，其他切片只判定自身局部门槛。

## 3. 切片定义

## TS-00 H5 核心运行时与微信入口

### 问题

H5 能否稳定完成录音、播放、触摸互动、SVG/Canvas/沙箱渲染、进度拖动、前后台恢复；微信能否可靠提供入口和必要权限？

### 最小实现

- H5 壳和最小微信入口壳；
- 20 秒音频、琴弦触摸场景、底部追问浮层；
- 前后台切换、网络中断和设备旋转；
- iOS/Android 微信、Safari/Chrome、iPad 和中端安卓平板。

### 候选通过条件

- 状态可预测，权限拒绝有回退；
- 音频暂停和恢复误差 P95 小于 250ms；
- 交互帧率 P95 不低于 30FPS；
- 旋转和前后台不丢失讲解现场；
- 明确记录纯小程序限制和 H5/WebView 边界。
- 记录媒体准备、首帧、暂停、恢复、触摸到可见反馈和前后台重建 span；按设备分别报告 P50/P80/P95、最大值和失败率。

## TS-01 输入、OCR、儿童语音与隐私预处理

沿用 v1 的识别准确率与隐私指标，增加主动授权的两种媒体生命周期：保留最多 30 天或处理后删除。原始媒体不得进入普通日志、内容数据库或 Git。

局部耗时分别记录 `input.asr`（停止说话到转写可见）、`input.ocr`（拍照完成到 OCR 可见）、本地隐私预处理和上传；按输入类型、设备、网络和成功/失败报告 P50/P80/P95、最大值与超时率。`input_result_visible → question_confirmed` 属于用户阅读、修改与决定时间，只作可用性观察，不计入系统处理性能。

## TS-02 教材解析、AI 核验与临时知识包

### 问题

系统能否从指定教材形成可追溯知识原子，将可靠外部来源组织为临时知识包，并在学段上下文可选的情况下，把无来源内容准确隔离到带提示的未核验生成路径，同时阻断冲突、误导和危险内容？

### 最小实现

- 小学科学声音与初中数学完全平方公式两个教材知识簇；
- 解析器、来源核验器、边界检查器、教学检查器、迁移检查器和发布裁决器；
- 来源存在性、哈希、页码、OCR 标记、提示注入、StageProfile、显式超前声明和跨学段来源规则由确定性代码执行；模型只承担证据语义、教学表达和迁移语义等不能由字段直接判定的检查；
- 来源冲突、缺页、扫描错误和诱导提示夹具；
- 学段、年级或教材版本缺失，以及跨学段来源串用夹具；
- 显式超前学习夹具；
- 运行时临时知识包使用同一来源层级；
- 无知识原子且无可靠来源时的未核验生成提示、状态和结果隔离。

### 指标与候选门槛

- 来源页码可追溯率 100%；
- 已填写 `StageProfile` 的字段完整率 100%；缺少学段上下文时自行猜测为 0；
- 缺少学段上下文和显式超前路径正常进入讲解的成功率 100%；
- 未声明的小学与初中来源串用为 0；
- 无来源关键结论被标记为已核验或临时已核验为 0；
- 无来源路径进入 `unverified_generated` 且固定 C 端提示覆盖率 100%；
- 未核验生成写入正式迁移学习结果为 0；
- 检查步骤冲突时错误发布为 0；
- Schema 合法率不低于 99%；
- 所有产物明确 `review_method=ai_only`；
- 阻断、未核验生成和视觉/媒体回退分别返回机器可读原因，不用一个“硬降级”状态混合表达。
- 本地确定性门禁与模型语义步骤分别统计，教学语义不得用结构布尔字段充当人工 oracle；进入真实模型比较前必须固定完整讲解文本、迁移题和人工评分 rubric。
- 模型语义步骤只影响 `verified|unverified` 等核验等级，不拥有缺学段、显式超前或无可靠来源问题的讲解阻断权；模型超时、格式失败或不确定时进入 `unverified_generated`。
- 辅助证据审核候选预检固定覆盖明确支持、部分支持、冲突、无关引用、双来源一致/冲突、无证据和证据内提示注入；单轮门槛为 Schema `8/8`、状态 `8/8`、原因码 `8/8`、危险误放行 `0/6`。
- 本地确定性门禁、模型证据审核和最终路由分别记录 span；按缓存、供应方、模型、结果和重试报告 P50/P80/P95、最大值、超时率、Token 与成本，不以单轮平均延迟作为稳定性结论。

2026-07-29 使用 PackyAPI 请求 `deepseek-v4-pro` 完成一次上述 8 例合成预检，达到全部候选门槛，使用 `5,487 Token`，平均延迟 `6,804 ms`，判定为辅助审核候选的 `conditional_pass`。该结果不证明重复稳定性、真实教材泛化、生产资格或聚合服务模型映射，也不改变本地确定性门禁拥有最终路由权的架构约束。

## TS-03 渐进讲解与迁移规划

### 问题

AI 核验知识能否在保留学段上下文的前提下转换为渐进讲解、视觉契约、静态降级和有效迁移任务？

### 最小实现

- 输出 2–4 个子片段；
- 分别运行小学科学声音、初中数学完全平方公式，以及同一声音核心关系的小学/初中受控配对夹具；
- 学段规则显式声明允许的前置知识、术语、公式密度、视觉信息量和迁移难度；
- 每段包含讲解目标、时间线 cue、渐进图解、视觉场景契约和降级；
- 首次迁移包含结论与因果验证；
- 失败后生成不同对象的新迁移情境；
- 关联主题不强制迁移。

### 候选门槛

- 计划 Schema 合法率不低于 99%；
- 关键顺序通过率不低于 90%；
- 学段上下文完整率 100%，使用未声明前置知识、跨学段来源或仅替换年级标签的计划为 0；
- 要求儿童先预测或等待作答的计划、换皮迁移和无降级片段为 0；
- 未经来源支持的关键事实为 0。
- 首个可用子片段、完整讲解计划、迁移题和静态降级计划分别记录 span；按学段、模型、成功/失败与重试报告 P50/P80/P95、最大值、Token 和成本。

### 当前结果（2026-07-30）

TS-03 使用 DeepSeek 官方 API `deepseek-v4-pro` 完成 `official-full-round-5`：4/4 请求返回、Schema 4/4；冻结输出在修正“前置知识可支持基础术语”的门禁误报后合同 4/4、双学段配对通过。人工学科与产品审核 4/4 通过，允许 TS-03 标记为 `pass`，无需新增模型轮次。完整计划延迟 P80 为 21,132ms，共记录 21,206 Token；真实账单成本仍未独立取得。

人工审核同时记录“讲解可能太简单、太简洁、内容较少”。数学案例覆盖了建模、配方和最大值理由，三个声音案例主要覆盖结论与对比，机制展开相对有限。该观察不推翻固定 4 例的审核通过结果，但本切片不证明讲解深度足以支持真实儿童理解。后续视觉审核与家庭测试应检查结论、原因/机制、可观察证据、条件边界和迁移是否形成完整推理链，不设置脱离教学目标的机械字数门槛。

## TS-04A 生成视觉代码沙箱

### 问题

任意生成视觉代码能否在不访问主应用和儿童数据的条件下安全运行、被限制并随时销毁？

### 必测攻击面

- 网络、Cookie、本地存储、主 DOM、摄像头、麦克风、剪贴板；
- 无限循环、内存增长、Worker/iframe 逃逸；
- 恶意 `postMessage`、事件洪泛和资源加载；
- 重复创建、崩溃和销毁后的残留状态。

### 候选门槛

- 禁止能力成功访问为 0；
- 超限代码可在预算内终止；
- 沙箱崩溃不影响主讲解和保存状态；
- 输入仅使用脱敏 Schema，输出仅限白名单事件；
- 每次执行可追溯到代码哈希和策略版本。
- 分别记录 iframe 创建、Worker 启动、代码执行、超限终止和销毁 span；正常执行与预期超时攻击不得混入同一个百分位分母。

### 问题

生成场景能否在展示前验证关键教学与布局不变量，并安全复用已验证产物？

### 最小实现
