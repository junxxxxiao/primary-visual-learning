## 唯一可证伪问题

在两个固定知识簇、一个合成临时知识包、两段受控教材章节和规定负向夹具上，同一版本化管线能否同时做到：

1. 将证据充分的教材内容发布为候选知识原子；
2. 将符合来源门槛的外部内容发布为临时知识包；
3. 在学段信息缺失或内容明确超前时继续讲解，且不猜测学段；
4. 将无知识原子且无可靠来源的内容隔离为 `unverified_generated`，展示一次固定提示且不写正式学习结果；
5. 阻断未声明的跨学段串源、严重核验冲突、OCR 污染和提示注入。

任一固定 oracle 路由错误、任一未核验内容被标记为已核验、任一未核验讲解写入正式结果、任一阻断样本被发布，或任一硬门槛未达到，答案即为“否”。即使固定夹具全部通过，本切片最多为“有条件通过”，因为尚未运行冻结配置的真实模型服务，也没有教师或学科专家审核。

## 明确非目标

- 不验证真实教材版面、表格、公式、插图或扫描 OCR 的泛化能力；
- 不验证模型供应商的准确率、稳定性、延迟、成本或调用独立性；
- 不验证教师审核、儿童可用性、学习效果、视觉生成或讲解时间线；
- 不声称覆盖小学至初中全年级、全部教材版本或两个固定知识簇以外内容；
- 不初始化 `apps/` 或 `packages/`，不锁定生产框架，不把 spike 代码提升为生产架构；
- 不自动把临时知识包或未核验生成内容升级为知识原子；
- 不为固定公开 Demo 新增设置页或动态提示页。

## 固定夹具与样本量

本切片固定运行 12 个确定性输入包：5 个预期发布、3 个预期未核验生成、4 个预期阻断。

| 路由 | 数量 | 固定夹具 | 预期 |
|---|---:|---|---|
| 发布 | 3 | 小学声音、初中完全平方、双来源真空声音 | 2 个候选原子，1 个临时知识包 |
| 发布 | 1 | 缺少年级的声音包 | 正常发布；`stage_fit=unknown`，不补猜年级 |
| 发布 | 1 | 显式声明的超前学习包 | 正常发布；`stage_fit=advanced` |
| 未核验生成 | 3 | 关键结论无证据、无原子且无可靠来源、引用页缺失 | 正常生成；固定提示；禁止正式学习结果 |
| 阻断 | 4 | 未声明跨学段串源、严重检查冲突、OCR 污染、提示注入 | `blocked`，不得发布 |

合成来源只表达验证管线所需事实，不是教材原文。`fixtures/source-manifest.json` 记录其 SHA-256、版本、页码和访问方式。

两份用户提供的教材 PDF 仅用于本地受控验证。`fixtures/controlled-sources.json` 只记录书名、学段、年级、许可状态、指定章节范围和 SHA-256；PDF 与正文不进入仓库。

## 版本化契约

- `schemas/stage-profile.schema.json`：完整 `StageProfile` v1.0；仅在信息已提供时校验，不要求用户必须填写；
- `schemas/stage-fit.schema.json`：`StageFit` v1.0，状态为 `within_stage|advanced|ambiguous|unknown`；
- `schemas/validation-input.schema.json`：验证输入 v1.0；
- `schemas/verification-step.schema.json`：独立检查步骤输出 v1.0；
- `schemas/knowledge-package.schema.json`：知识包输出 v1.1。

系统不得根据题目难度、措辞或儿童身份猜测缺失学段。输出保留来源哈希、版本、页码、`verification_status`、`stage_fit`、路由原因和用户提示，所有产物固定标记 `review_method=ai_only`。

## 独立核验步骤

1. `parse`：检查输入页、OCR 标记和提示注入，不决定发布。
2. `source_verification`：逐条检查来源、文件哈希、页码和证据摘录，不做教学判断。
3. `boundary_check`：判断已知学段、声明的超前路径、来源混用和步骤冲突，不猜缺失信息。
4. `pedagogy_check`：检查前置知识和表达约束，不核验来源真实性。
5. `transfer_check`：检查迁移任务是否要求结论和原因，不决定来源等级。
6. `release_decision`：只消费前五步结构化结果，输出 `publish|unverified_generate|block`。

没有可靠来源不是阻断理由，进入未核验生成。严重冲突、OCR 污染、提示注入和未声明跨学段串源进入阻断。媒体/动画失败的静态回退属于另一层，不与内容核验状态混用。

## 决策规则

- 全部硬门槛通过，但仅有合成管线与受控章节静态核对：`conditional_pass`；
- 任一安全或核验硬门槛失败：`fail`；
- 只有补齐真实模型重复运行、独立核验和人工评审分母后，才可重新评估完整通过；
- 两个固定教材夹具不得外推为全年级或跨教材覆盖。

## 数据、版权与隐私边界

- 不提交未经授权教材 PDF、教材正文、扫描页、真实儿童照片、语音、问题、身份资料、生产日志或密钥；
- 受控教材只在用户提供的本地路径读取指定章节，仓库仅保存哈希、页段、字符数、文本哈希和访问说明；
- 外部来源必须能识别机构/作者、版本、发布日期和原始页面。搜索摘要、论坛、个人自媒体、无版本资料和模型记忆不能作为已核验依据；
- 临时知识包优先使用课标/教材、政府/公共教育机构、权威出版物；缺少单一优先来源时至少需要两个独立且一致的高质量来源；
- 未核验生成不缓存为已核验内容，不产生正式学习结果或长期画像；
- 本 spike 不访问网络、不持久化用户数据，也不包含真实儿童数据。

2026-07-29 的首轮 PackyAPI `deepseek-v4-flash` 运行已完成，机器汇总见 `results/model-deepseek-v4-flash-round-1.json`。该配置只达到 `7/12` 路由准确、`53/60` Schema 合法，并发生 `1/60` 请求超时，判定为失败；未获授权也未启动后续轮次。第三方聚合服务返回的实际模型标识为 `deepseek-v4-flash-202605`，其模型映射和计费不能按 DeepSeek 官方 API 结论外推。

随后经用户确认，仅对上述 7 个 Schema/超时失败步骤关闭思考模式做定向预检，结果见 `results/model-deepseek-v4-flash-retry-no-thinking.json`：Schema、状态和原因码均为 `7/7`，使用 `7,084` Token。该结果通过格式门槛，但不是完整第二轮，不能替代首轮失败结论；它说明后续完整复测应使用关闭思考的冻结配置，而不是继续增加输出预算。

经再次确认后，使用请求参数 `thinking.type=disabled` 完整运行 12 例、60 步，结果见 `results/model-deepseek-v4-flash-full-no-thinking.json`：路由 `10/12`、Schema `55/60`、步骤状态 `57/60`、原因码 `52/60`，合计 `47,707` Token，60 次请求均返回，平均延迟 `8,476 ms`。但 60/60 个响应仍包含 `reasoning_content`，其中 5 个因达到长度上限而截断，证明 PackyAPI 或其上游没有实际执行关闭思考请求。该配置仍为失败，不得表述为无思考模式验证通过。

最后按混合职责运行一次：本地确定性代码处理来源存在性、哈希、页码、OCR、提示注入、StageProfile、超前声明、前置知识字段和迁移布尔标志，只把 5 个本地发布候选交给模型做 15 个语义步骤。结果见 `results/model-deepseek-v4-flash-hybrid.json`：本地路由 `12/12`，模型 Schema `14/15`，最终路由 `8/12`，共 `17,913` Token，结论为失败。失败同时暴露现有正向夹具不具备教学语义 oracle 所需的完整讲解和迁移文本；例如 `missing_stage_context` 的迁移提示只有“Compare a tuning fork.”，却由布尔字段声明为同时要求结论和理由。因此该结果不能单独归因于模型质量，也不能通过修改 oracle 追求表面通过。

上述混合运行仍把模型语义失败聚合成 `block`，现仅作为“模型不得拥有最终路由权”的历史失败证据保留。调整后的职责是：本地确定性规则决定 `publish|unverified_generate|block`；模型只判断证据是否支持候选结论。模型不确定、超时、格式失败或语义拒绝时，普通问题最多降为 `unverified_generate`，不得阻断缺少年级、明确超前或无可靠来源的讲解。

V4 Pro 的聚焦证据审核只运行 8 个合成样例：明确支持、部分支持、单来源冲突、无关引用、双来源一致、双来源冲突、无证据和证据内提示注入。运行命令为：

```bash
TS02_MODEL=deepseek-v4-pro \
  python3 spikes/ts-02-knowledge-validation/run_model_evidence_audit.py
```

该运行器最多调用 8 次，不读取教材 PDF、教材提取正文或儿童数据。候选门槛为 Schema `8/8`、支持判断 `8/8`、原因码 `8/8`，并且 6 个预期拒绝样例中危险误放行必须为 `0/6`。即使达到门槛也只能记为一次运行的 `conditional_pass`，不能证明重复稳定性、广泛学科准确率或生产资格。

2026-07-29 的 PackyAPI `deepseek-v4-pro` 聚焦运行达到 Schema `8/8`、支持判断 `8/8`、原因码 `8/8`、危险误放行 `0/6`，使用 `5,487 Token`，平均延迟 `6,804 ms`，8 次响应均正常结束但都包含 `reasoning_content`。机器结果见 `results/model-deepseek-v4-pro-evidence-audit.json`。本轮记为 `conditional_pass`：它只证明该请求配置在一次小型合成样本中具备辅助证据审核候选资格，不证明重复稳定性、真实教材泛化、教育正确性或 PackyAPI 模型映射；实际费用仍须查看 PackyAPI 账单。

## 已验证与未验证

已验证的是固定数据形状、确定性路由、原因码保留、指定章节的局部证据存在性、未核验内容的状态隔离，以及 V4 Pro 在一次 8 例合成证据审核中的候选表现。未验证的是模型重复运行稳定性、真实教材与真实搜索泛化、OCR 泛化、学科专家准确性评审、儿童学习效果、生产稳定性和 PackyAPI 实际费用。
