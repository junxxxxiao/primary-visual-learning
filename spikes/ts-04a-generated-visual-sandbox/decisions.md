# TS-04A 决策记录

- 日期：2026-07-29
- 结论：**有条件通过（固定 Chromium 攻击矩阵通过）**
- 基线：`origin/main` at `27c80343836dcd88b10b8abd9ceacf57d1567a95`
- 负责人：Codex 技术切片执行

## 决策

允许 TS-04B 以“沙箱 iframe 内的 Dedicated Worker + OffscreenCanvas”作为候选执行边界继续验证。生成代码不得直接操作 DOM；主应用不得把儿童资料、对话、历史、原始媒体或凭证放入沙箱输入。

固定 Chromium 的 11 个攻击夹具全部通过，禁止能力成功访问为 0；3 个非法输入全部拒绝；20 次重复创建/销毁全部完成且无残留 iframe。无限循环、持续内存增长、事件洪泛和超大输出均被终止，生成代码崩溃未改变主讲解模拟状态。每次执行均记录代码 SHA-256 和策略版本。

结论只为有条件通过，因为当前证据来自单一 Headless Chromium，时间预算只是限制内存增长窗口，不是独立的进程级堆上限；也尚未进行 WebKit/微信 WebView 验证、长期压力或专业渗透测试。

## 分段耗时补充

后续补跑按共享 `stage-timing/1.0` 契约记录 `sandbox.create`、`sandbox.worker_boot`、`sandbox.execute`、`sandbox.terminate` 和 `sandbox.destroy`。执行预算从 `worker-ready` 开始，Worker 启动另行统计；否则启动较慢的设备会在生成代码尚未执行时被错误判为执行超时。

20 次生命周期样本的 P50/P80/P95/max 为 128/191/231/254ms；31 次 Worker 启动为 41.2/51.7/88.6/200.9ms；两个无限执行样本在 251.5ms 和 252.4ms 被终止。该结果只证明局部阶段可观测且执行预算语义正确，不构成生产性能门槛。样本来自一台机器上的单一 Headless Chromium，无移动设备、并发或真实内容负载；平均值不作为决策指标，TS-06 仍是唯一端到端耗时裁决切片。

## 对 PRD 的影响

无需修改当前 PRD 的用户流程。技术上把“任意生成视觉代码”收窄为受控 Worker 视觉程序；如果 TS-04B 证明该格式不足以承载目标教学场景，需回到 PRD/ADR 重新决定表达能力与隔离强度的取舍。

## 对高保真与公开 Demo 的影响

无页面或交互变更。公开 Demo 仍是人工编排内容，不接入本 spike。TS-04B 之前不得把动态场景展示给儿童。

## 对架构的影响

- 主应用只持有输入校验、生命周期和最终展示控制权；
- 不透明源 sandbox iframe 承担权限与来源隔离；
- Dedicated Worker 承担不可信代码执行和可终止性；
- `OffscreenCanvas` 是唯一绘制出口，私有 `MessagePort` 是唯一事件出口；
- CSP 中的 `unsafe-eval` 仅存在于无 `allow-same-origin` 的隔离 iframe，用于装载生成代码，主应用不得继承该策略；
- TS-04B 必须在展示前追加教学正确性和 ADR-0003 布局门禁。

## 对数据与隐私的影响

沙箱输入 Schema 只允许场景标识、尺寸和脱敏参数，并递归拒绝已知身份、声音、照片、原话和历史字段。当前夹具全部为合成数据，不访问网络、不调用模型、不保存用户数据。生产前仍需使用显式参数白名单替代仅靠敏感键黑名单，并验证日志、崩溃报告和缓存不会带入儿童数据。

## 仍未验证范围

- Safari/WebKit、iOS、Android Chrome、微信 WebView 及不同浏览器版本；
- 进程级 CPU/堆内存硬配额、超大 structured clone 和浏览器级拒绝服务；
- CSP/Permissions Policy 的服务端生产配置与旁路测试；
- 浏览器漏洞、计时/缓存侧信道和第三方专业渗透；
- 屏幕阅读器、键盘/触控、视觉正确性、布局边界、缓存和端到端降级；
- 长时间、并发、多场景和前后台压力。
- 真实设备上的分段耗时分布、端到端用户等待及生产性能 SLO。
