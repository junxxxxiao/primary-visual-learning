# 陌生问题讲解质量参照合同

## 参照的是什么

声音与数学 Demo 是人工编排的 `reference_fixture`。参照的是它们的讲解完整度和运行行为，不是题目、DOM、CSS、视觉对象或专用动画实现。

每个候选陌生问题至少需要达到以下结构质量：

1. 先完整展示当前子片段的起始画面并静置 1,000ms；
2. 使用 3–6 个具有明确教学作用的 beat，而不是把一句结论拉长；
3. 每个 beat 的旁白、视觉动作和观察焦点同步开始并指向同一事实；
4. 讲解按需要覆盖现象或题意、关键关系、推理过程、结论与条件边界；不能机械凑段数；
5. 暂停冻结旁白、进度和已经出现的画面，恢复从同一位置继续；
6. 手机采用同一语义场景的响应式重组，不是压缩平板画面，也不是模型另生成一版；
7. 减少动态效果和失败降级仍保留推理顺序与完整结论。

## 场景接口质量

- 节点必须是通用矢量原语，题目名称不得成为新的节点类型或动作类型；
- 动画必须呈现对理解有用的变化，例如路径、数量、位置、形状、关系或数值变化；纯入场、漂浮或标签闪烁不算教学动作；
- 每个动作必须引用已声明节点，每个关键事实必须至少被一个 beat 和静态降级引用；
- 逻辑构图使用单一场景；可信渲染器根据手机/平板安全区域重排 group，并计算全部运动包络；
- 不允许 JavaScript、HTML、CSS、SVG 字符串、外部 URL、任意表达式或设备专属代码。

## 人工硬门槛

产品视觉与学科审核分别给出 `pass/fail`，不能用平均分互相抵消。

产品视觉失败条件包括：看不出当前要观察什么、变化只是装饰、主体过小、信息堆叠、手机只是平板缩小版、旁白与动画不同步、暂停恢复改变现场，或整体明显低于 Demo 的讲解完整度。

学科失败条件包括：严重事实或公式错误、因果链颠倒、关键条件遗漏、图形与旁白矛盾，或静态降级改变结论。

儿童理解仍需后续有授权的可用性研究，本合同不能替代儿童证据。

## 自动运行状态

可信渲染器后续必须对每个视口分别检查：

- `start`
- `key_process`
- `final`
- `paused`
- `resumed`
- `after_interaction`
- `reduced_motion`
- `static_fallback`

这些状态由本地程序从一份 timeline 确定性执行。模型不需要生成 16 份状态，也不应把状态声明重复写进输出。
