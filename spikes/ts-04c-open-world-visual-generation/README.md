# TS-04C-v3 陌生问题开放视觉生成

> 状态：`fail`；v0.3 人工评审未达标，v0.4 质量修订候选合同 5/10
> 性质：TS-04C 的独立候选框架，不是候选模型能力证据
> 基线：`origin/main` at `5e002d1d4e04ec70e71ecd6c3b3b8af299d1e34f`

## 唯一验证问题

冻结候选模型能否针对未见过、且不复用声音或完全平方公式 Demo 题目的用户问题，一次生成完整的通用矢量场景图与 3–6 拍旁白时间线，并经可信本地渲染器在手机和平板上形成可展示、可理解且符合安全边界的讲解？

## 为什么另立候选

TS-04C-v2 的四类 DSL 模板通过了机器门禁，但 10/10 动画被产品视觉人工审阅判定为不可展示，0/10 具备完整多拍旁白。陌生问题不能假设仓库里已经存在对应题型模块，因此本切片不以“找到模板再拼装”为核心能力。

模型只跨一个声明式 seam：已运行的候选输出 `open-visual-scene/0.2`；v0.1、v0.2 原文件与候选证据保持冻结。首轮浏览器门禁发现 v0.2 没有定义 `x/y` 的坐标锚点，下一 harness 接口 `open-visual-scene/0.3` 固定使用中心点坐标，但尚未产生 v0.3 候选输出。可信渲染模块负责响应式重排、手机/平板适配、8 个运行状态、统一播放、安全检查和静态降级。模型不得输出 JavaScript、HTML、CSS 或设备专属两版代码。

## 固定校准夹具

`fixtures/calibration-inputs.json` 包含 10 道与 Demo 不同的 synthetic 陌生问题：

- 4 道：陌生措辞或情境，但可借用常见视觉语法；
- 3 道：熟悉概念，但必须形成新构图；
- 3 道：概念和视觉表达都更陌生。

夹具标为 `gold_fixture` 或 `adversarial_fixture`，只用于验证框架和后续校准，不是教材或权威知识证据，也不得计入候选正式评测分母。

## 输出接口

`schemas/open-visual-scene.schema.json` 保留 v0.1；`schemas/open-visual-scene-v0.2.schema.json` 是当前候选接口。两版都只允许：

- 通用节点：`group`、`shape`、`line`、`text`、`axis`、`plot`、`formula`、`particles`；
- 受限动作：`show`、`hide`、`emphasize`、`move`、`scale`、`rotate`、`morph`、`trace`、`compare`、`update_value`；
- 每份讲解 3–6 个 beat，每个 beat 包含旁白、时长和视觉动作；
- 1,000ms 起始画面静置；
- 与事实引用绑定的 3–6 步静态降级。

逻辑坐标和布局意图只描述一份场景；设备尺寸、最终边界与运行时状态由可信渲染模块计算。

## 计划门槛

候选运行获授权后，校准轮必须同时满足：

- 10/10 输出通过 Schema、事实绑定和代码文本拦截；
- 10/10 具备 3–6 个有效讲解 beat，旁白、视觉动作和事实引用可逐拍对应；
- 手机/平板各 8 状态的沙箱、边界、运动包络、暂停恢复和静态降级检查全部通过；
- 产品视觉人工评为可展示不少于 8/10，学科严重错误为 0；
- 失败样本 100% 不展示、不缓存，并使用同一合同下通过门禁的静态降级；
- 校准通过后才能冻结参数并另行决定是否设计正式轮，不能沿用旧候选的正式 40 例直接开跑。

儿童是否真正理解、学习效果和生产稳定性不由本切片宣称。

## 候选校准结果

2026-07-31 完成 DeepSeek 官方 `deepseek-v4-pro` 的 10 例校准：10/10 收到响应，零重试、零修复，总用量 48,835 Token；模型耗时 P80 为 23,367ms，最大 27,317ms。6/10 通过 Schema、事实绑定、引用完整性和代码文本门禁，低于预设的 10/10 门槛。

四个失败分别为未声明节点引用、单动作目标超过 Schema 上限、`morph` 需要 Schema 未允许的 `height`，以及动作时间越过所属 beat。前两类包含模型合同遵循问题，后两类同时说明 `open-visual-scene/0.1` 的动作接口和约束还不够成熟。

本轮结论为 `fail`。浏览器渲染、手机/平板 8 状态和人工视觉/学科评审未启动；这不是动画质量通过或失败的证据，而是候选尚未取得视觉评审资格。6 个合同通过输出只保留作接口诊断，不进入展示或缓存。

## v0.2 复测结果

v0.2 只把动作目标上限从 8 调到 20，并允许动作改变 `width/height`，没有放宽事实、安全、节点引用或时间门禁。首轮冻结响应只改版本号后离线重放达到 8/10，证明两个已知接口缺口被移除；该重放是 `diagnostic_replay`，不算候选证据。

同一 DeepSeek 配置重新生成 10 例后，10/10 收到响应，但只有 5/10 通过，总用量 49,709 Token，模型耗时 P80 23,708ms。四个失败使用 Schema 未允许的 `children` 或非字符串 `parent_id`，另一个失败改写了唯一 claim ID。结果没有随接口修复改善，反而从 6/10 降到 5/10。

因此冻结 v0.2，不再继续放宽接口或追加 DeepSeek 同配置轮次。下一验证应让支持严格结构化输出的另一模型或服务在相同 10 题、Schema、参数边界和门槛下做对照；在新候选明确授权前不调用其他模型。

## V4 Flash 对照授权

用户于 2026-07-31 将本地候选切换为 DeepSeek 官方 `deepseek-v4-flash` 并要求复测。本轮保持 v0.2、相同 10 题、`temperature=0`、关闭 thinking、每次最多 5,000 输出 Token、60 秒超时、零重试/修复、10 请求与 100,000 Token 上限；只发送相同 synthetic unverified 数据。使用独立 run label，不覆盖 V4 Pro 证据。

Flash 对照轮 10/10 收到响应，7/10 通过合同，总用量 49,489 Token；P80 13,941ms，最大 17,068ms。相同 v0.2 下，V4 Pro 为 5/10、P80 23,708ms，因此 Flash 的合同通过率提高 20 个百分点，P80 缩短约 41%。

三个失败仍是格式遵循：直线使用未允许的 `x1/y1/x2/y2`、布局优先级超出 1–5，以及无父节点时输出非字符串 `parent_id`。Flash 明显优于 Pro，但仍低于进入浏览器与人工动画评审的 10/10 门槛，结论仍为 `fail`。不能只渲染 7 个成功样本来改变固定分母。

用户随后授权一次受控修复轮：只修复上述 3 个失败输出，每题最多一次、总计最多 3 请求和 30,000 Token；模型、v0.2、固定参数与数据边界不变，不重新生成首次已通过的 7 题。

## Flash 受控修复与浏览器结果

受控修复 3/3 收到响应且 3/3 通过 v0.2 合同，使用 19,103 Token，P80 为 13,324ms。合并后仍保持固定 10 题分母：7 个首次通过输出加 3 个修复输出，最终合同为 10/10。修复结果不改写 Flash 首轮 7/10，也不是正式评测分母。

可信本地渲染器随后在真实 Chromium 中对 10 个合并候选执行手机和平板各 8 状态，共 160 次运行。7/10 候选通过；影子、移动直线交点和勾股拆拼 3 个候选触发 `browser.logical_bounds` 与 `browser.screen_bounds`。人工学科与产品视觉评审没有启动，动画质量仍未验证。

失败样例暴露的是 v0.2 接口歧义：Schema 只限制 `x/y/width/height` 的数值范围，却没有说明 `x/y` 是元素中心还是左上角。渲染器按中心点解释时，三个样例越界；若按左上角解释，其他既有输出又可能改变。不得逐元素猜测或用启发式选择锚点，因此本轮分类为接口失败，不能归因为模型视觉质量，也不能把 7 个浏览器通过样例送去人工评审改变固定分母。

`open-visual-scene/0.3` 仅用于修复该接口缺口：`scene.coordinate_space.anchor` 必须为 `center`，所有节点 `x/y` 与动作 `to.x/to.y` 都是中心点，点列仍是绝对坐标；候选门禁在外部调用或展示前检查初始几何和 `move/scale/rotate/morph` 的运动包络。旧 v0.2 输出只保留为冻结证据，不自动迁移、不重新解释为 v0.3 candidate_output。再次调用模型前仍需重新确认模型版本、固定参数、请求和 Token 预算及数据边界。

## v0.3 Flash 校准结果

用户确认沿用 DeepSeek 官方 `deepseek-v4-flash`、`temperature=0`、关闭 thinking、每次最多 5,000 输出 Token、60 秒超时、零自动重试和零修复，以独立 10 请求、100,000 Token 上限运行 v0.3；仍只发送相同 synthetic unverified 数据。10/10 请求收到响应，总用量 54,641 Token，P80 15,382ms、最大 23,645ms，但合同仅 5/10 通过。

五个失败均为模型没有遵守已给出的 Schema，而不是新增坐标接口缺口：影子、等值分数和移动直线交点三题继续使用未允许的 `x1/y1/x2/y2`；影子与杠杆两题使用超过 1–5 的 `layout.priority`；周长面积反例题大量生成不符合小写 ID 规则的标识符。没有失败来自 `center` anchor、初始几何或运动包络检查。

本轮低于 10/10 合同门槛，因此浏览器和人工评审按停止条件均未启动。结论仍为 `fail`：v0.3 已解决坐标歧义，但当前 Flash 配置的严格结构遵循能力不足，仍没有产生陌生问题动画质量证据。下一步不应继续放宽 Schema 接受这些变体；应对照支持严格 JSON Schema 结构化输出的模型或服务，或在重新授权后只对 5 个失败样例做一次受控修复。

## 完整格式实例提示

下一提示配置 `v03-complete-format-example/0.1` 不再只要求“遵守 Schema”，而是同时提供一份没有省略号、字段带真实值且能通过同一 v0.3 门禁的完整 JSON 实例。实例覆盖：

- 顶层字段、`center` 坐标空间和合法小写 ID；
- 8/8 节点类型，含 `line` / `plot` 的 `geometry.points` 实际写法；
- 合法 `parent_id`、1–5 优先级、中心点几何和点列几何；
- 10/10 动作类型及各自的 `target_ids`、`to`、`value` 和时间字段；
- 3 拍旁白时间线、交互目标、事实引用和静态降级。

提示还明确给出常见错误反例：禁止 `x1/y1/x2/y2`、`children`、`null parent_id`、大写或中文 ID、超出 1–5 的优先级，以及对 point 节点做几何变换。系统同时要求只复制结构，不复制示例的 `sample_id`、claim、文案或数值。

实例标记为 `gold_fixture` / `synthetic_format_only`，只证明提示与门禁管线，不计为候选输出或模型能力证据。当前状态为 `harness_ready`，外部请求为 0；再次测试前仍需冻结新的 run label、模型版本、参数、请求与 Token 预算和数据边界。

## 完整实例提示候选结果

用户确认沿用相同 DeepSeek 官方 `deepseek-v4-flash`、v0.3、固定参数、10 请求、100,000 Token 上限和 synthetic unverified 数据边界，仅把提示替换为 `v03-complete-format-example/0.1`。10/10 请求收到响应，合同 10/10 通过，总用量 72,796 Token；P80 15,327ms、最大 18,668ms，零自动重试与零修复。完整实例消除了上一轮出现的直线别名、超范围优先级和非法 ID。

真实 Chromium 随后完成手机/平板各 8 状态共 160 次运行，10/10 候选通过，无逻辑边界、屏幕边界、空白画布或单色画布违规。唯一控制台错误是无关的 `favicon.ico` 404。

该结果只把状态推进到 `candidate_run_complete`。人工产品视觉和学科评审尚未开始；机器门禁不能判断标签重叠、构图稀疏、教学变化是否清晰或动画是否达到声音/数学 Demo 的质量。`review-harness.html` 提供真实时间线播放、手机/平板切换、暂停、拖动、逐题评分、严重错误标记和 JSON 草稿导出。

## v0.3 人工评审与运行时修复

产品负责人完成固定 10 题人工评审：1 题可展示、7 题需要修改、2 题不可展示。主要问题是图形对象不可辨认、公式或构成关系缺失、旁白描述的变化没有同步落实到画面，以及直线和勾股题的图形语义错误。原始评审保存在 `results/ts04c-v03-human-review-round-1.json`，该轮结论为 `fail`。

评审后还确认可信渲染器没有真正绘制旋转、`trace` 会立刻显示完整路径、评审播放器不响应减少动态效果。三项运行时缺陷已经修复，并新增真实 Chromium 像素回归；旋转、渐进描画、普通/减少动态时间线与旧候选手机/平板 160 状态全部通过。该修复只纠正播放真实性，不改变旧候选的人工失败结论。

## v0.4 语义质量候选

`open-visual-scene/0.4` 保留声明式安全边界，只增加通用多边形、箭头和形状内对象标签，并要求每个 `required_explanation_aspects` 原样绑定到真实节点和讲解拍。提示配置为全部 22 条格式与质量规则提供正反例，重点覆盖对象可辨认、公式/坐标自检、同步关系变化、闭合电路、等分/拼图完整性和无用途节点禁令。

用户确认继续使用 DeepSeek 官方 `deepseek-v4-flash`、`temperature=0`、关闭 thinking、每次最多 5,000 输出 Token、60 秒超时、零重试/修复、10 请求和 100,000 Token 上限，只发送同一 synthetic unverified 夹具。10/10 请求收到响应，使用 84,818 Token，P80 14,105ms、最大 16,593ms，但合同只有 5/10：

- 影子和杠杆题尝试移动 point-based 线，暴露 v0.4 尚不支持动态端点的接口缺口；
- 分数和凝结题的 aspect binding 引用了不存在的 beat；
- 直线题生成了坐标范围外的点。

由于低于 10/10 合同门槛，v0.4 浏览器候选门禁和人工复评均未启动。本轮结论仍为 `fail`，不能用 5 个通过样例改变固定分母，也不追加未授权修复覆盖首轮结果。
