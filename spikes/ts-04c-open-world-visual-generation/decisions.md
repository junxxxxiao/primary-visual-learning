# TS-04C-v3 决策

- 日期：2026-07-31
- 状态：`fail`
- 结论：v0.3 机器门禁虽通过，但人工评审仅 1/10 可展示；修复运行时并增加 v0.4 语义能力后，新候选合同仅 5/10，未取得人工复评资格

## 已完成

- 用 10 道非 Demo synthetic 问题覆盖三档陌生度；
- 将声音和数学 Demo 降为 `reference_fixture`，只提取完整讲解质量；
- 定义通用矢量节点、受限动作、3–6 拍旁白时间线和静态降级接口；
- 把响应式布局、8 状态、播放和安全检查留在可信本地渲染模块；
- 增加无网络的夹具与 Schema 自测。

## 未验证

- 其他模型、参数或改版 Schema 能否达到候选门槛；
- v0.3 候选的真实浏览器结果；
- 学科与产品视觉人工通过率；
- 儿童理解、生产延迟、稳定性和成本。

## 候选证据

- 10/10 请求收到响应，响应模型均为 `deepseek-v4-pro`；
- 固定参数为关闭 thinking、`temperature=0`、每次最多 5,000 输出 Token、60 秒超时、零重试与零修复；
- 总用量 48,835 Token，其中输入 27,213、输出 21,622；实际账单成本未独立取得；
- 模型耗时 P80 23,367ms，最大 27,317ms；
- 6/10 通过候选合同，4/10 失败；正式评测分母仍为 0。

## 失败分析

- 影子题：timeline 两处引用未声明节点；
- 等值分数题：单动作包含 9 个目标，超过 Schema 的 8 个上限；
- 串联电路题：`morph` 使用 `height`，但动作目标 Schema 未提供宽高变化；
- 液体分层题：一个动作的结束时间越过所属 beat。

这些失败同时包含模型合同遵循问题和 `open-visual-scene/0.1` 接口设计不足。由于预设门槛要求 10/10 合同通过，本轮按停止条件不启动浏览器 8 状态与人工评审；6 个通过输出仅用于诊断，不视为可展示候选。

## v0.2 独立候选轮

- v0.2 仅把动作目标上限从 8 提升到 20，并允许 `to.width` / `to.height`，事实绑定、节点引用、代码拦截和时间门禁保持不变；
- 首轮冻结响应做版本号替换后的诊断重放为 8/10，但该产物不是 `candidate_output`；
- v0.2 新轮 10/10 收到响应，5/10 合同通过，总用量 49,709 Token，P80 23,708ms；
- 4 个失败来自模型输出未允许的 `children` 或非字符串 `parent_id`，1 个失败来自模型改写唯一 claim ID；
- 两轮累计 20 次请求、98,544 Token，实际账单成本均未独立取得。

v0.2 新轮没有改善合同通过率，说明继续为单次输出变体扩大接口会降低 seam 的清晰度，并不能建立稳定能力。本轮同样不启动浏览器与人工评审。

## 影响

- 对 PRD：无流程变化，陌生问题能力仍是未验证的核心假设。
- 对高保真设计：Demo 继续作为质量下限参照，不扩成题型模块库。
- 对架构：模型只跨一个声明式场景/timeline seam；可信渲染模块提供响应式、状态与安全的深实现。
- 对数据和隐私：仅 synthetic 夹具；不含儿童数据、真实教材、凭据或生产日志。

## 下一步门禁

冻结 `open-visual-scene/0.2` 和当前 10 题，不再为 DeepSeek 输出增加 `children`、`null parent_id`、直线别名或超范围数值兼容。下一候选仍应优先选择支持严格 JSON Schema 结构化输出的模型或服务；若继续 Flash，必须另立一次受控修复候选并重新授权，不能把修复结果混入本轮首次生成分母。

## Flash 受控修复

- 首轮合同结果仍为 7/10，修复不计为新的正式分母，实际账单成本未取得。

## 首轮真实浏览器门禁

- 10 个合并候选在真实 Chromium 中完成手机和平板各 8 状态，共 160 次运行；
- 7/10 候选通过，3/10 同时触发逻辑边界和屏幕边界违规；

- 浏览器控制台唯一错误是未提供 `favicon.ico` 的 404，与门禁结果无关；
- 人工学科和产品视觉评审未启动，动画质量、旁白质量和陌生问题讲解效果仍未验证。

## 接口判定与 v0.3

`open-visual-scene/0.2` 没有规定节点 `x/y` 和动作 `to.x/to.y` 是中心点还是左上角。渲染器按中心点解释，而三个候选明显包含左上角式构图。逐元素用启发式猜测会隐藏接口歧义并破坏安全证据，因此本轮判为接口失败，不判为模型视觉失败。

下一 harness 接口 `open-visual-scene/0.3` 固定 `scene.coordinate_space.anchor = "center"`，并在候选门禁中检查初始几何和全部变换动作的保守运动包络。已增加缺失 anchor、把左上角误当中心点和运动终点越界的负向回归。v0.2 输出不自动迁移，离线重放也只能作为 `diagnostic_replay`。

## v0.3 Flash 校准

- 授权配置：DeepSeek 官方 `deepseek-v4-flash`、`temperature=0`、关闭 thinking、每次最多 5,000 输出 Token、60 秒超时、零重试/修复、10 请求、100,000 Token 上限；
- 数据边界：只发送相同 synthetic unverified 题目与 claims，不发送教材、儿童数据或生产日志；
- 10/10 收到响应，总用量 54,641 Token，P80 15,382ms、最大 23,645ms；
- 合同通过 5/10，低于必须 10/10 的门槛；浏览器与人工评审未启动；
- 三题仍使用未允许的 `x1/y1/x2/y2`，两题使用超范围 `layout.priority`，一题同时大量使用不符合小写规则的 ID；
- 没有出现 `center` anchor、初始几何或运动包络违规，说明 v0.3 的已知接口缺口被封闭，当前失败属于模型结构遵循。

结论保持 `fail`。不能通过兼容直线别名、扩大优先级或放宽 ID 规则来追逐输出变体。后续若修复这 5 个失败或换用支持严格 JSON Schema 的候选，必须重新确认模型/服务、固定参数、请求与 Token 预算和数据边界。

## 完整实例提示配置

根据产品负责人要求，下一提示配置 `v03-complete-format-example/0.1` 为所有严格输出家族提供一份完整、带实际值且经门禁验证的 JSON 实例，而不是只给抽象 Schema 或省略号片段。实例覆盖 8 种节点、10 种动作、坐标、ID、父子引用、优先级、时间线、事实绑定、交互和静态降级；自然语言规则同时展示合法直线 `points` 与禁用 `x1/y1/x2/y2` 等正反例。

该实例是 `gold_fixture` / `synthetic_format_only`，不得计入候选分母，也不得作为题目事实复用。离线测试 14/14 通过，实例自身通过 v0.3 Schema、事实绑定和运动包络门禁。当前只推进到 `harness_ready`，没有发起新的模型请求；下一候选运行仍需独立授权与 run label。

## 完整实例提示候选轮

- 模型、参数、10 请求、100,000 Token 和数据边界与无实例 v0.3 轮相同，唯一变量是加入完整合法实例；
- 10/10 收到响应，合同 10/10，总用量 72,796 Token，P80 15,327ms、最大 18,668ms，零重试/修复；
- 真实 Chromium 手机/平板各 8 状态共 160 次，10/10 候选通过，无边界或空白画布违规；

- 人工评审为 `not_started`，不得把机器结果表述为动画质量通过。

候选已取得人工评审资格。评审播放器按真实时间插值动作，保留 1 秒起始静置，支持手机/平板、暂停、拖动、逐题评分、严重错误和备注导出。首次视觉抽查已看到标签压图和构图稀疏风险，因此当前不能给出 `conditional_pass|pass`。

## 人工评审与 v0.4 决策

- v0.3 人工评审：1/10 可展示、7/10 需要修改、2/10 不可展示，结论为 `fail`；
- 运行时修复：真实旋转、渐进 trace 和减少动态效果已通过 Chromium 像素回归，旧候选 160/160 状态仍通过；
- v0.4 新增通用多边形、箭头、对象内标签和 aspect-to-node/beat 绑定，不增加题型专用组件或任意代码；
- v0.4 DeepSeek Flash 10/10 收到响应，合同 5/10，使用 84,818 Token，P80 14,105ms；
- 两个失败暴露动态 point 端点接口缺口，三个失败属于候选引用和几何合同错误；
- 按停止条件不启动 v0.4 浏览器候选门禁和人工复评，不追加修复。

最终决策保持 `fail`。PRD 和高保真不变；架构上继续保留受限声明式场景与可信渲染器，但进入下一候选前必须先决定是否为动态关系线定义明确的端点绑定/重算语义，并重新确认候选调用预算。
